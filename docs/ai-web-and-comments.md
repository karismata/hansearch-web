# 내부 자료 우선 AI 검색과 자료별 댓글

## 검색 흐름

- 정확히 일치하는 저장된 수정 답변은 기존처럼 즉시 재사용한다.
- 그 외 질문은 Mac의 로컬 스냅샷에서 의미 검색한 후보를 한주AI가 평가한다.
- `sufficient`: 해결 근거가 있는 내부 답변. 웹검색은 사용자 버튼으로 선택한다.
- `partial`: 일부 근거만 안내하고 인터넷 보완 검색 버튼을 표시한다.
- `none`: 관련 없는 후보는 검색 결과에서 제외하고 자동 웹검색한다.
- `unknown`: 모델의 잘못된 구조/인용 등 판단 실패. 자료 없음으로 처리하지 않고 후보와 수동 웹검색을 제공한다.
- 사용자는 내부 답변 생성 중에도 인터넷 검색을 요청할 수 있다. 별도 작업에서 검색을 먼저 진행하고 내부 답변은 유지한다. 같은 내부 작업의 자동 웹검색과 중복되지 않도록 부모 작업을 표시한다.
- 검색 단계를 중계하고, 먼저 확인한 내부 결과를 웹검색 완료 전에도 보여준다. 다른 검색어로 전환한 뒤 도착한 이전 결과는 표시하지 않는다.

Tavily Search API는 Mac에서만 호출한다. 사용자의 질문과 공개 검색어만 전송하며, 내부 자료 본문/댓글/DB 키/중계 키는 전송하지 않는다. 질문에서 파악한 기기·증상에 맞는 검색어만 보강하고 제조사 지원 자료를 검색한다. 모든 질문에 포스·키오스크·단말기를 일괄 추가하지 않는다. 검색은 최대 4개 후보를 받고, 기기·증상 선별 후 최대 2개를 웹 답변 모델에 전달한다. 내부 후보는 최대 4개이며 각 발췌는 1,200자로 제한한다. 최종 답변은 로컬 Ollama에서 생성한다. 긴 본문의 뒤쪽에만 있는 해결책은 발췌에서 빠질 수 있으므로 화면의 원문 자료와 수동 웹검색을 계속 제공한다. 도메인 선호만으로 자료의 정확성이나 관련성을 보장하지 않는다.

`search_depth=basic`, `auto_parameters=false`, `include_answer=false`, `include_raw_content=text`를 명시하여 기본 검색 한 번으로 정리된 웹페이지 본문도 받는다. 두 번째 자동 검색, advanced, extract, hosted AI 답변, 유료 공급자 fallback은 없다. 진단은 본문을 요청하지 않는다. Tavily 공식 안내(https://docs.tavily.com/documentation/api-credits)에 따르면 Researcher 무료 플랜은 매월 1,000크레딧, basic 요청은 1크레딧이다. 본문 포함은 응답 시간이 늘어날 수 있다(https://docs.tavily.com/documentation/api-reference/endpoint/search). 무료 플랜의 Development 키를 쓰고 PAYGO/자동 충전을 켜지 않는다. 스크립트는 결제·요금제 API를 호출하지 않는다. 앱 코드만으로 외부 계정의 유료 설정을 변경하거나 차단하는 것은 아니다.

`web_intent`로 대상 기기(포스 본체/프린터/키오스크/카드 단말기/리더기)와 주된 증상(전원/급지·인쇄/통신/인증/결제/부팅/화면)을 별도로 추정한다. 질문과 제목의 기기·증상이 명확히 충돌하면 본문에 전원·어댑터 같은 공통 점검 단어가 있어도 제외한다. 제목에서 파악하지 못한 항목만 본문 발췌로 보완한다. 예를 들어 포스 본체 전원 질문에 `POS 프린터 종이 공급 문제`를 근거로 쓰지 않으며, 포스 전원 글에 주변 프린터 분리 단계가 있다는 이유로 정상 자료를 제외하지도 않는다. `포스 프린터`는 프린터로, `프린터를 분리해도 포스가 안 켜짐`은 포스로 구분한다. `포스 단말기`와 별도 카드 단말기도 구분한다.

기기·증상 선별을 통과한 자료 중 단어가 겹치지 않는 후보는 제외하고 관련성→본문 확인 여부→제조사 도메인 선호 순으로 정렬한다. 모든 후보가 제외되면 그 링크를 근거로 표시하지 않고 일반 점검 제안으로 구분한다. 검색 요청은 계속 한 번이며 별도의 분류 모델/추가 웹검색 요청은 없다. 캐시 버전은 `intent-v4`로 구분한다. 로그는 기기·증상 분류와 사용/제외 숫자만 표시한다. 이 분류는 제한된 표현을 이용한 보수적인 규칙이며, 모든 제품명·복합 질문의 의미적 관련성이나 조치 정확성을 보장하지 않는다. 파악하지 못한 항목은 unknown으로 남기고 로컬 답변 모델에도 기기·주증상을 확인하도록 지시한다.

웹 답변은 핵심 점검 3~4개와 판단 한 문장, 전체 600자 이내를 목표로 요청한다. 한 문장이 85자를 넘는 것만으로 전체 답변을 폐기하지 않는다. 구조와 출처 번호는 검증하고, 850자를 넘으면 로컬에서 한 번 다시 정리한다. 문장 중간을 잘라 조건·주의사항이 빠지게 하지 않는다. JSON 코드 블록 감싸기는 제거하고 읽는다. 본문 인용은 `body`, 검색 요약이 포함된 인용은 `snippet`, 출처 없는 일반 제안은 `general`로 구분한다. 검색 요약을 썼다는 이유만으로 유효한 점검 답변 전체를 폐기하지 않고, `검색 요약 참고·원문 미확인`을 답변과 제목에 명시한다. 본문 확인과 동일한 근거로 표시하지 않는다. 잘못된 자료 번호·임의 URL은 계속 거부한다. 회사 소개·사전 정의·FAQ 목차와 다른 증상의 해결책을 섞지 않도록 지시한다. 구조·출처 검증은 조치의 정확성까지 보장하지 않으므로 현장 확인은 계속 필요하다.

형식이 잘못되거나 지나치게 긴 답변은 로컬 모델에서 한 번만 다시 요약한다. 추가 Tavily 검색은 하지 않는다. 웹 요약의 생성 토큰은 첫 요청 1,200, 재정리 1,600으로 한정하며 `done_reason=length`는 생성 제한으로 분류한다. 내부 검색의 기존 설정은 유지한다. 로컬 연결/시간 초과에는 재시도를 반복하지 않는다. `answer_format/answer_length/answer_citation`과 `model_timeout/model_output_limit/model_connection` 등을 로그와 오류 코드로 구분한다. 모델 원문이나 키는 로그에 기록하지 않는다. 그래도 실패하면 짧은 안내만 보여주고 원문을 답변에 붙이지 않는다. 참고 링크는 답변 바로 아래에 항상 표시하며 기존 외부 링크 동작(웹 새 탭, Android 앱 외부 브라우저)을 사용한다. 긴 본문 발췌는 기본으로 접힌 `출처·원문 보기`에서 확인한다. 이전 Mac 서버가 긴 원문 fallback을 반환해도 웹화면이 이를 감지해 접힌 영역으로 옮긴다. 저장된 사용자 수정 답변은 자동으로 잘라내지 않는다.

영상 자막 오인식과 SNS 안내가 해결책에 섞이지 않도록 기본 검색에서 YouTube/Instagram/Facebook/TikTok 도메인을 제외한다. API에서 제외 도메인이 반환되어도 서버에서 한 번 더 걸러낸다.

같은 질문의 유효한 검색 발췌는 Mac 메모리에 6시간(최대 128질문) 보관하여 사용자 간 재사용한다. 키 값은 캐시에 저장하지 않고 질문/키 해시로 분리한다. 동시에 같은 질문을 검색해도 외부 요청은 한 번만 보낸다. 오류와 빈 결과는 캐시하지 않고, 서버 재시작 시 캐시는 비워진다. 재사용한 자료는 접힌 출처 영역의 설명에 표시하며, 최종 AI 답변을 자동으로 검증답변으로 저장하지 않는다. 무료 한도 초과(432/433) 시 안내하고 내부 검색은 유지한다. 남은 무료 크레딧은 Tavily 계정의 다른 사용량과 설치 진단 요청도 포함한다.

웹 발췌문 속 지시는 실행하지 않도록 안내한다. 실제 반환된 출처 번호/URL만 표시한다. 일반 진단 제안은 AI 추정으로 구분하며 설정값/비밀번호/초기화를 근거 없이 생성하지 않도록 안내한다. 웹검색 또는 답변 분석이 실패하면 기존 내부 결과와 확보한 출처 링크를 유지한다. 웹검색 결과를 자동으로 검증답변에 저장하지 않는다. 사용자가 `답변 수정·저장`을 눌러 확인한 답변만 저장한다. 이때 웹 출처 링크도 편집 내용에 포함한다. 기존 데이터 추가와 자료 수정·삭제는 그대로 사용할 수 있다.

웹에서도 자료를 찾지 못하면 확인된 사례가 없음을 표시하고, 로컬 모델의 일반 점검 제안을 `AI 일반 점검 · 현장 확인 필요`로 구분한다. 검색키 미설정이나 검색 서비스 연결 실패를 근거 없음으로 해석하지 않는다.

## 맥미니 업데이트 (한 번)

웹사이트/Worker 배포만으로 Mac의 Python 파일은 바뀌지 않는다. 기존 서버를 Control+C로 멈춘 뒤, 기존 `.env`가 있는 폴더에서 실행한다. ZIP 폴더이므로 `git pull`을 사용하지 않는다.

```bash
cd "/Users/elt/Documents/Hansearch AI/hansearch-web-codex-local-ai-sync/local-ai"
curl -fL https://raw.githubusercontent.com/karismata/hansearch-web/main/local-ai/enable-web-search.command -o enable-web-search.command
bash enable-web-search.command
```

스크립트가 Tavily API 키를 화면에 표시하지 않고 입력받는다. 발급 위치: https://app.tavily.com/ . 무료 Researcher 플랜의 Development 키를 사용한다. `TAVILY_API_KEY`는 기존 Cloudflare `AI_ACCESS_TOKEN` 및 예전에 설정한 `OLLAMA_API_KEY`와 다른 키다. 예전 Ollama 검색키는 보존하지만 새 서버에서는 사용하지 않는다. 채팅·GitHub·브라우저 설정에 넣지 않는다. 모든 사용자가 Mac 서버의 연결을 사용하므로 사용자별 입력이 필요 없다.

스크립트는 `.env`와 기존 서버를 백업하고, 기존 DB/중계 설정과 `data` 스냅샷은 유지한다. 새 키로 기본 검색 한 번을 진단하여 HTTP 200일 때만 서버를 교체/시작한다. 진단 실패 시 기존 `server.py`는 유지하고 수정한 `.env`와 백업은 남긴다. 업데이트 후 `[web] 인터넷 검색: Tavily · 키 설정됨`, `[relay] Cloudflare 연결 확인`을 확인한다. 실제 모델 답변까지의 성공은 한서치에서 확인한다. `[ai] … retrieving / analyzing / web_search / web_analysis`로 진행 단계와 경과 시간을 확인할 수 있다. 키 미설정/인증 실패/한도/네트워크 문제는 웹화면에 별도 안내한다. APK는 기존 사이트를 불러오므로 다시 만들 필요가 없다.

기존 Tavily 키가 정상 동작하면 재입력 없이 `local-ai/update-local-ai.command`를 같은 폴더에 다운로드해 실행한다. 기존 서버를 Control+C로 종료한 뒤 실행하며 `.env`는 수정하지 않는다. 새 서버 문법 검사 후 `--check-answer`로 실제 로컬 모델에 공개 예제 점검을 요청한다. 이 단계에서는 웹검색·DB·중계·HTTP 서버를 시작하지 않는다. 실제 Mac 모델이 형식 검사를 통과해야 기존 키 연결 진단 한 번, 서버 백업/교체/시작으로 진행한다. 실패하면 기존 서버 파일은 유지하고 원인 코드만 출력한다. 예제 검사 통과는 실제 질문의 답변 정확성까지 보장하지 않는다.

## 인터넷 검색 연결 진단

`인터넷 검색에 연결하지 못했습니다`만으로는 요청 한도 초과를 확정할 수 없다. Python 서버는 401(인증), 403(접근 거부), 429(빈도 제한), 432/433(이용 한도), 434(혼잡), 5xx(검색 서비스 오류), DNS·TLS·시간 초과를 구분하고 오류 코드만 기록한다. 응답 원문과 키는 표시하지 않는다.

같은 `local-ai` 폴더에서 최신 서버 파일로 `python3 server.py --check-web-search`를 실행하면, 기존 `.env` 설정을 이용해 일반적인 공개 검색어로 한 번만 요청한다. 로컬 HTTP 서버/모델/DB 동기화를 시작하지 않으므로 기존 서버를 켜둔 채 별도 터미널에서 진단할 수 있다. 구버전 서버를 덮어쓰기 전에 검사하려면 최신 파일을 `.hansearch-web-check.py`라는 이름으로 같은 폴더에 받아 `python3 .hansearch-web-check.py --check-web-search`를 실행한다. 이 임시 파일에는 키를 기록하지 않는다.

## 댓글 권한과 표시

- 승인된 계정만 읽기/등록이 가능하다. 자료별 `댓글`을 눌렀을 때만 요청하고 최신 댓글부터 30개씩 불러온다.
- 자료 목록을 읽을 때 `info_comments(count)`로 댓글 숫자만 함께 받아 접힌 버튼에도 표시한다. 댓글 본문은 계속 열었을 때만 가져온다. 등록/삭제/댓글 새로고침의 총 개수는 상위 목록 상태에도 반영하여 검색어 전환 후에도 유지한다. DB 구조/권한 변경이나 자료별 추가 HTTP 요청은 없다.
- 작성자 이름·작성 시각은 DB에서 기록한다. 자신의 댓글 수정/삭제, 마스터는 다른 사람의 댓글 삭제가 가능하다.
- 댓글은 최대 4,000자이며 일반 텍스트로 표시한다. HTML을 실행하지 않는다.
- 계정이 삭제되어도 기존 댓글의 작성자 이름은 보존하고, 자료가 삭제되면 해당 댓글도 함께 삭제한다.
- 댓글은 처리 경험을 공유하는 영역이다. 자동으로 AI의 검증 근거에 포함하지 않는다. 검증된 내용은 자료 수정 또는 답변 수정·저장으로 반영한다.
- `public.info_comments`에 RLS와 명시적인 열 권한을 적용한다. 작성자·자료 ID·시간의 클라이언트 위조를 차단한다. 기존 다른 앱 테이블/권한은 변경하지 않는다.

## 댓글 답글과 앱 내 알림

- 댓글에 한 단계의 답글을 달 수 있다. 답글 목록과 작성 폼은 해당 댓글의 `답글 보기·작성`을 눌렀을 때만 불러온다. 댓글/답글은 각각 최신순 30개씩 불러온다. 최상위 댓글 페이지와 답글 페이지를 분리하여 부모 댓글이 페이지 밖으로 빠지는 문제를 피한다.
- 자료의 댓글 숫자는 답글까지 포함한 총 개수다. 댓글/답글 등록·삭제 후 카드의 숫자를 반영한다. 원래 댓글 삭제 시 답글도 함께 삭제됨을 확인 창에 명시하고, DB cascade 후 전체 개수를 다시 읽는다. 기존 댓글 작성자/마스터의 삭제 권한을 유지하며 답글 수정은 작성자만 가능하다.
- DB가 부모 댓글의 존재, 같은 자료 소속, 최상위 댓글 여부를 검사한다. 클라이언트가 다른 자료에 답글을 붙이거나 부모를 바꾸거나 세 번째 단계의 댓글을 만드는 것을 차단한다.
- 새 댓글은 등록자가 기록된 자료의 작성자에게, 새 답글은 원래 댓글 작성자와 자료 작성자에게 알린다. 동일 수신자는 한 번만 알리고 본인 작성과 승인되지 않은 수신자는 제외한다. 등록자가 없는 기존 자료에는 자료 작성자 알림을 소급 생성하지 않는다. 과거 댓글도 소급 알리지 않는다.
- 알림은 상단 종 아이콘의 안 읽은 개수와 목록으로 제공한다. 목록은 열었을 때 최신순 20개씩 불러온다. 로그인한 화면이 보이는 동안 안 읽은 숫자만 약 60초마다 확인하며, 화면으로 돌아오거나 알림 목록을 열 때도 확인한다. 운영체제 푸시/문자/이메일 알림은 보내지 않는다.
- 알림 클릭 시 자료 제목과 해당 댓글의 대화를 별도 창에서 보여주고 읽음 처리한다. 해당 대화만 보다가 자료의 모든 댓글로 전환할 수 있다. 새 검색·필터 상태를 초기화하지 않는다. 삭제된 자료/댓글은 연결된 알림도 삭제되며, 열린 화면에서 뒤늦게 삭제된 대상은 안내를 표시한다.
- 알림은 DB의 비공개 트리거 함수가 생성한다. 승인된 수신자 본인만 SELECT/읽음 변경이 가능하고, 마스터도 다른 사용자의 알림은 볼 수 없다. 클라이언트 INSERT 및 수신자/자료/행동/작성 시각 변조 권한은 없다. 함수 실행 권한은 모든 API 역할에서 회수한다.
- `20261104040519_comment_replies_and_notifications.sql`은 부모 컬럼, FK, 조회 인덱스, 알림 테이블·정책·트리거를 추가한다. 실제 DB 적용 이력은 `20261104041417_comment_replies_and_notifications`이다. 기존 행은 최상위 댓글로 유지하며 기존 댓글 본문/작성자를 변경하지 않는다. Mac 서버나 APK 재생성은 필요하지 않다.

## 검증 범위

Python 테스트: 충분/부분/없음/판단 실패, 수동 검색의 내부 검색 생략, 중복 자동 검색 방지, 잘못된 인용/URL 차단, 키 미설정/실패, 외부 요청에 내부 자료가 없는지 확인.

DB 테스트: 익명/미승인/삭제 계정 거부, 승인 계정 댓글, 작성자 위조 방지, 본인 수정/삭제, 마스터 삭제, 계정 삭제 후 표시 보존, 자료 삭제 시 cascade.

Worker/UI 테스트: 기존 세션/소유자 분리, 웹검색 모드와 구버전 Mac 차단, 부분 진행/최종 답변, 내부 분석 중 수동 검색, 내부 답변 유지, 출처 포함 수정 저장, 이전 질문 응답 무시, 댓글 지연 로딩/안전한 텍스트 표시.

실제 Mac 모델의 답변 품질과 처리 시간, 실제 Tavily 검색 인증은 사용자 Mac 업데이트 후 확인해야 한다. 자동 테스트는 외부 검색/모델을 모의하며 실제 검색을 성공했다고 간주하지 않는다.
