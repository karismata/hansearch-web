# 내부 자료 우선 AI 검색과 자료별 댓글

## 검색 흐름

- 정확히 일치하는 저장된 수정 답변은 기존처럼 즉시 재사용한다.
- 그 외 질문은 Mac의 로컬 스냅샷에서 의미 검색한 후보를 한주AI가 평가한다.
- `sufficient`: 해결 근거가 있는 내부 답변. 웹검색은 사용자 버튼으로 선택한다.
- `partial`: 일부 근거만 안내하고 인터넷 보완 검색 버튼을 표시한다.
- `none`: 관련 없는 후보는 검색 결과에서 제외하고 자동 웹검색한다.
- `unknown`: 모델의 잘못된 구조/인용 등 판단 실패. 자료 없음으로 처리하지 않고 후보와 수동 웹검색을 제공한다.
- 사용자는 내부 답변 생성 중에도 인터넷 검색을 요청할 수 있다. 별도 작업에서 검색을 먼저 진행하고 내부 답변은 유지한다. 같은 내부 작업의 자동 웹검색과 중복되지 않도록 부모 작업을 표시한다.
- 검색 단계를 중계하고, 먼저 확인한 내부 결과를 웹검색 완료 전에도 보여준다. 다른 검색어로 전환한 뒤 도착한 이전 결과는 표시하지 않는다.

Ollama hosted web-search API는 Mac에서만 호출한다. 사용자의 질문과 공개 검색어만 전송하며, 내부 자료 본문/댓글/DB 키/중계 키는 전송하지 않는다. 공식 매뉴얼·제조사 고객지원 검색어로 먼저 검색하고, 결과가 적으면 일반 검색을 한 번 추가한다. 운영자가 지정한 제조사 도메인 결과를 우선 정렬한다. 내부/웹 자료 발췌는 최대 4개, 각 1,200자로 제한하고 최종 답변은 로컬 Ollama에서 생성한다. 긴 본문의 뒤쪽에만 있는 해결책은 발췌에서 빠질 수 있으므로 화면의 원문 자료와 수동 웹검색을 계속 제공한다. 도메인 선호만으로 자료의 정확성이나 관련성을 보장하지 않는다.

웹 발췌문 속 지시는 실행하지 않도록 안내한다. 실제 반환된 출처 번호/URL만 표시한다. 일반 진단 제안은 AI 추정으로 구분하며 설정값/비밀번호/초기화를 근거 없이 생성하지 않도록 안내한다. 웹검색 또는 답변 분석이 실패하면 기존 내부 결과와 확보한 출처 링크를 유지한다. 웹검색 결과를 자동으로 검증답변에 저장하지 않는다. 사용자가 `답변 수정·저장`을 눌러 확인한 답변만 저장한다. 이때 웹 출처 링크도 편집 내용에 포함한다. 기존 데이터 추가와 자료 수정·삭제는 그대로 사용할 수 있다.

웹에서도 자료를 찾지 못하면 확인된 사례가 없음을 표시하고, 로컬 모델의 일반 점검 제안을 `AI 일반 점검 · 현장 확인 필요`로 구분한다. 검색키 미설정이나 검색 서비스 연결 실패를 근거 없음으로 해석하지 않는다.

## 맥미니 업데이트 (한 번)

웹사이트/Worker 배포만으로 Mac의 Python 파일은 바뀌지 않는다. 기존 서버를 Control+C로 멈춘 뒤, 기존 `.env`가 있는 폴더에서 실행한다. ZIP 폴더이므로 `git pull`을 사용하지 않는다.

```bash
cd "/Users/elt/Documents/Hansearch AI/hansearch-web-codex-local-ai-sync/local-ai"
curl -fL https://raw.githubusercontent.com/karismata/hansearch-web/main/local-ai/enable-web-search.command -o enable-web-search.command
bash enable-web-search.command
```

스크립트가 Ollama 검색 API 키를 화면에 표시하지 않고 입력받는다. 발급 위치: https://ollama.com/settings/keys . `OLLAMA_API_KEY`는 기존 Cloudflare `AI_ACCESS_TOKEN`과 다른 키다. 채팅·GitHub·브라우저 설정에 넣지 않는다. 모든 사용자가 Mac 서버의 연결을 사용하므로 사용자별 입력이 필요 없다. 서비스 이용 한도는 Ollama 계정에서 확인한다.

스크립트는 `.env`와 기존 서버를 백업하고, 기존 DB/중계 설정과 `data` 스냅샷은 유지한다. 업데이트 후 `[web] 인터넷 검색: 사용 가능`, `[relay] Cloudflare 연결 확인`을 확인한다. `사용 가능`은 키가 설정되었다는 의미이며 실제 인증/한도 성공은 첫 검색에서 확인한다. `[ai] … retrieving / analyzing / web_search / web_analysis`로 진행 단계와 경과 시간을 확인할 수 있다. 키 미설정/인증 실패/한도/네트워크 문제는 웹화면에 별도 안내한다. APK는 기존 사이트를 불러오므로 다시 만들 필요가 없다.

## 인터넷 검색 연결 진단

`인터넷 검색에 연결하지 못했습니다`만으로는 요청 한도 초과를 확정할 수 없다. 업데이트한 Python 서버는 401(인증), 403(접근 거부), 429(요청 제한), 5xx(검색 서비스 오류), DNS·TLS·시간 초과를 구분하고 오류 코드만 기록한다. 응답 원문과 키는 표시하지 않는다. 선택적인 두 번째 검색이 실패해도 첫 검색에서 확보한 자료는 유지한다.

같은 `local-ai` 폴더에서 최신 서버 파일로 `python3 server.py --check-web-search`를 실행하면, 기존 `.env` 설정을 이용해 일반적인 공개 검색어로 한 번만 요청한다. 로컬 HTTP 서버/모델/DB 동기화를 시작하지 않으므로 기존 서버를 켜둔 채 별도 터미널에서 진단할 수 있다. 구버전 서버를 덮어쓰기 전에 검사하려면 최신 파일을 `.hansearch-web-check.py`라는 이름으로 같은 폴더에 받아 `python3 .hansearch-web-check.py --check-web-search`를 실행한다. 이 임시 파일에는 키를 기록하지 않는다.

## 댓글 권한과 표시

- 승인된 계정만 읽기/등록이 가능하다. 자료별 `댓글`을 눌렀을 때만 요청하고 최신 댓글부터 30개씩 불러온다.
- 작성자 이름·작성 시각은 DB에서 기록한다. 자신의 댓글 수정/삭제, 마스터는 다른 사람의 댓글 삭제가 가능하다.
- 댓글은 최대 4,000자이며 일반 텍스트로 표시한다. HTML을 실행하지 않는다.
- 계정이 삭제되어도 기존 댓글의 작성자 이름은 보존하고, 자료가 삭제되면 해당 댓글도 함께 삭제한다.
- 댓글은 처리 경험을 공유하는 영역이다. 자동으로 AI의 검증 근거에 포함하지 않는다. 검증된 내용은 자료 수정 또는 답변 수정·저장으로 반영한다.
- `public.info_comments`에 RLS와 명시적인 열 권한을 적용한다. 작성자·자료 ID·시간의 클라이언트 위조를 차단한다. 기존 다른 앱 테이블/권한은 변경하지 않는다.

## 검증 범위

Python 테스트: 충분/부분/없음/판단 실패, 수동 검색의 내부 검색 생략, 중복 자동 검색 방지, 잘못된 인용/URL 차단, 키 미설정/실패, 외부 요청에 내부 자료가 없는지 확인.

DB 테스트: 익명/미승인/삭제 계정 거부, 승인 계정 댓글, 작성자 위조 방지, 본인 수정/삭제, 마스터 삭제, 계정 삭제 후 표시 보존, 자료 삭제 시 cascade.

Worker/UI 테스트: 기존 세션/소유자 분리, 웹검색 모드와 구버전 Mac 차단, 부분 진행/최종 답변, 내부 분석 중 수동 검색, 내부 답변 유지, 출처 포함 수정 저장, 이전 질문 응답 무시, 댓글 지연 로딩/안전한 텍스트 표시.

실제 Mac 모델의 답변 품질과 처리 시간, 실제 Ollama 검색 인증은 사용자 Mac 업데이트 후 확인해야 한다. 자동 테스트는 외부 검색/모델을 모의하며 실제 검색을 성공했다고 간주하지 않는다.
